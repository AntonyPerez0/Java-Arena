# Fidelity suite

Java Arena computes every expected output with a real JDK 21 at build time, and grades learners' code with the in-browser engine. They must agree. This suite checks that they do.

- `programs/NN-name/`: 48 small programs in the style of the course. Each has `Main.java` (some also have other classes in files of their own, or in their packages' folders, such as `library/domain/Book.java`), and optionally `stdin.txt`, `files/` (put in the program's working folder, subfolders too) and `meta.json` (`args`, `nondeterministic`, `note`). A program that uses `javafx.` runs with Java Arena's practice version of JavaFX on its class path, as on the site (`src/grader/libraries.js` decides it for both). Together they cover Scanner input, `HashMap` and `HashSet` order (also with keys of the program's own classes, after the map has grown and had keys removed), double and float printing, `printf` rounding, seeded `Random`, `Math`, integer overflow, strings, streams, records and enums, comparators, interfaces, inheritance (an abstract class, a chain of subclasses with super calls, an interface several classes implement, `instanceof` and casts, `Object`'s methods through a subclass, and `List`, `Map`, `Set` and `Collection` variables), the techniques of part 10 (`StringBuilder`, regular expressions with `matches`, `replaceAll` and `split` and the messages of invalid ones, an enum with a constructor and methods, iterators that remove, `Comparable` and sorting with `Comparator.comparing`, `thenComparing` and `reversed`, streams with `reduce`, `IntStream`, `boxed`, `Collectors.joining` and `groupingBy`, and `Files.lines`), classes in packages (imports, full names, package-private and `protected` access), the techniques of part 12 (generic classes with one and two type parameters, a generic interface and generic methods, a list of the program's own that grows and compiles with javac's note about unchecked operations, a hash map of its own with buckets of key-value pairs and keys with negative hash codes, seeded `Random` with `nextInt`, `nextDouble`, `nextBoolean`, `nextGaussian`, `ints` and `Collections.shuffle`, and two-dimensional arrays: filled, summed by row and column, jagged, `Arrays.deepToString`, a `String[][]`, and the rows of a `boolean[][]` created in one `new`, cloned, copied, swapped and compared), the messages of the part's mistakes caught (a negative array size, a bound of 0, a negative list capacity, an `Object[]` used as a `String[]`), caught and uncaught exceptions (with causes and exit codes, `finally`, multi-catch, try-with-resources, and an exception class of the program's own), the messages of list, array and string index errors, number parsing errors and null pointers (including the JVM's "helpful" null pointer messages), arrays and their default values, files through `java.io` and `java.nio.file` (also appended to, written into new folders, and the messages when a folder is missing), `java.time`, stack overflow, `System.exit` (also with -1 and inside a static initializer), `Thread.sleep`, a misspelled and an inherited `main`, and a CPU-heavy program. Program 48 uses Java Arena's practice version of JavaFX (`engine/libraries/javafx/`): `launch` with parameters, `init` and `start` on their threads, most of its API (every pane, label, button and text input, fonts, insets, string properties and listeners, the children lists' rules), a second window, and `files/.arena/events.txt` with every kind of event (`click`, `type`, `set`, `enter`, `close`, targets by number, id, text and count), events that can't happen (each a problem in plain English), an exception in a handler, and `Platform.runLater` (also with a null task); the window JSON it writes, `.arena/window.json`, is compared byte for byte like any other file. `npm run fx-check` also runs it on real OpenJFX 21 (`scripts/fx-check/`).
- `errors/NN-name/`: 68 programs that must not compile, the mistakes beginners make most. From 19 on they are the mistakes of inheritance and interfaces: a missing abstract method, an interface method without `public`, a parent without a constructor that takes no values, `super(...)` after other statements, an `@Override` that replaces nothing, `new` on an abstract class or an interface, `implements` and `extends` swapped, a subclass's method called through the parent's type, a parent-type value put in a subclass variable, a parent's private variable used in a subclass, method bodies where there must be none, and an `@Override` in a class whose header uses the wrong keyword or on a method named like a static method of its parent. From 32 on they are the mistakes of part 10: a lambda that uses a local variable that changes, a lambda that gives back the wrong type or nothing, stream methods called on an array, a list or a map, an `Optional` used as a number, `Comparable` and `Comparator` without a type in angle brackets and sorting objects that aren't `Comparable`, `new` on an enum and a `public` enum constructor, an enum constant without its enum's name, and a lambda parameter that Java types as `Object` after `Comparator.comparing(...)`, also when two of the program's classes have the method the lambda calls. From 41 on they are the mistakes of exceptions and packages: a catch for an exception its try can't throw, catches in the wrong order and a multi-catch of related exceptions, a `try` on its own, `throw` with text or without `new`, a line after `throw`, an overriding method that adds `throws`, a catch's variable used after its block, unreported exceptions around files (also in a lambda, a constructor and a try-with-resources), a class of another package without its import, imports of packages and classes that don't exist, a class, a constructor or a member used from another package without `public` or with `protected`, a package line that doesn't match its folder, and a public class in a file of another name. From 55 on they are the mistakes of part 12: a primitive type in angle brackets (`List<int>`), `new T[10]`, `new T()`, an `Object[]` for a `T[]` and an array of a type with angle brackets, a value of the wrong type given to or taken from a generic class (also through `new Box<>(...)` and a variable without its type in angle brackets, and a class that implements a generic interface without one), a static member that uses the class's type parameter, two-dimensional arrays (a row where one value is wanted and the other way round, a missing pair of brackets, an initializer without the rows' braces, an index too many, a grid passed where a row is wanted), and `new Random(...)` with text, a decimal number or two values. From 61 on they are the mistakes of part 13, with Java Arena's practice version of JavaFX on the class path: JavaFX classes without their imports (also with a star import of another package), classes, packages and methods that real JavaFX has and the practice version doesn't (and misspelled ones), `launch` in or with a class that doesn't extend `Application`, `start` misspelled, with other parameters or another return type, `static` or missing, checked exceptions in `start` and `stop`, event handlers and change listeners that change a local variable (lambdas and an inner class), handlers with the wrong number of parameters, a `void` call or a value given to `setOnAction` instead of a handler, a method reference to a method that doesn't take the event, the list `getChildren()` gives (several nodes given to `add`, a `GridPane`'s cell, other kinds of list, `=` on it), values of the wrong type for `setScene`, `setPadding`, `setAlignment`, `setFont` and `setText`, `new Scene()`, `getChildren()` on a `Button` and on a `Scene`, and a `Node` from `getChildren()` or `lookup` used as the `Button` or `Label` it holds.

Run it:

```bash
npm run fidelity:jdk        # the reference: javac and java from JAVA_HOME or the path
npm run build && npm run fidelity:browser   # the same suite through the built site in headless Chromium
```

`FIDELITY_ONLY=<regular expression>` (the same for both commands) runs only the programs and error cases whose folder names match, while working on something.

`fidelity:browser` compares each program's stdout (byte for byte), exit code, the first line of stderr and the learner's own stack frames, and the files the program wrote (in subfolders too). It also runs two cross-checks that separate the halves of the engine: classes compiled by the browser's javac run on HotSpot, and classes compiled by the command-line javac run on the browser's JVM. For the error programs, every line javac prints must be identical, apart from file paths and the final `N errors` count line. The command-line javac runs in the sources' folder with that folder as its class path, as the browser's compiler has it, so a class it finds there by itself (in a file whose package line doesn't match its folder, say) is named the same way. The report is written to `fidelity/out/report.md`, and CI fails on any difference.

On the JDK, a JavaFX program runs through `arena.reference.JavaFxLauncher` (`scripts/javafx/`): the JDK's own launcher refuses a main class that extends `javafx.application.Application` when JavaFX isn't a module of the JDK ("JavaFX runtime components are missing"), while the browser engine just calls `main`. The launcher calls `main` with its own stack frames hidden, so traces, messages and exit codes are those of `java Main`.

The reference JDK is Eclipse Temurin 21.0.10+7 (`scripts/get-jdk.sh`, or `JAVA_HOME` if set), the same build the engine's class library comes from. It runs with `-Duser.language=en -Duser.country=US -Duser.timezone=UTC`, UTF-8 encodings and `-XX:+UnlockDiagnosticVMOptions -XX:-UseLibmIntrinsic` (so `Math.sin` and friends match what an interpreter computes). Program 29 prints an identity hash code (`Main$Book@...`), which differs between any two runs; only that part is ignored.
